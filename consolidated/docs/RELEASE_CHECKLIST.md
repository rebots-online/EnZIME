# Complete-to-market checklist

11 September 2026. The local implementation has advanced beyond the original
market skeleton. **Checked local items describe the bounded implementation or
specific evidence below; they do not certify the corresponding full PRD gate.**
The mature PRD remains the product contract. See
[LOCAL_ENGINE_RELEASE.md](LOCAL_ENGINE_RELEASE.md) for implementation boundaries
and exact inference evidence.

## B. Reader beta — full PRD and release gates

### DynDon across every ZIM path

- [ ] **DD-01:** qualify coordinated storage budgets on representative devices,
  including linked models, caches, concurrency, reserve, peak staging,
  disk-full and interrupted recovery. Local planner tests are not the full matrix.
- [ ] **DD-02/03:** qualify taxonomy quality, balanced topic coverage and actual
  breadth/depth selection on Wikipedia and non-Wikipedia corpora. Prepared-unit
  selection exists; a universal corpus taxonomy does not.
- [ ] **DD-04:** publish edition-bound prepared manifests or Creator-generated
  coherent subsets for arbitrary allocations. Verify complete resources and
  offline reading; arbitrary partial ZIM bytes are insufficient.
- [ ] **DD-05/08:** network-disabled reboot/rehearsal and interrupted transfer
  acceptance with representative sources, notes, search and unavailable services.
  Local pause/resume/hash tests do not certify the entire readiness contract.
- [ ] **DD-06:** reversible grow/shrink with pinned material, notes and final
  work protected; interrupted resize and rollback evidence.
- [ ] **DD-07:** battery/memory qualification and verified SD/USB/LAN transfer,
  including explicit handling of private notes.
- [ ] **DD-09:** every Creator/editor regeneration path uses the shared planner;
  qualify actual compressed size, cancellation and atomic commit. The local
  uncompressed-ZIM writer does not complete the whole authoring pipeline.
- [ ] **DD-10:** EnZIME/Sanctissimissa common download/generation integration,
  source-capability discovery and supported fallbacks.

### Reader, storage and platforms

- [ ] **ZIM-01/02:** canonical cross-platform AnZimmerman integration, hostile
  fixture qualification, multipart requirements and native/browser conformance.
  The working Node format adapter is not a Rust FFI completion.
- [ ] **READ-01/02:** 500-page/scanned-book qualification, OCR policy,
  thumbnails/continuous rendering, annotation rectangles and screen-reader
  acceptance. Text-layer/page-search code alone does not close this gate.
- [ ] **READ-03:** EPUB conformance, complex HTML/resource fidelity and restart
  navigation across supported browsers/devices.
- [ ] **READ-05/06:** anchor reattachment/orphan repair across changed editions,
  large annotation sets and complete user-facing exports.
- [ ] **LIB-02/03:** edition/work identity, long-running transfers, quotas and
  recovery qualification beyond local regression fixtures.
- [ ] **STORE-04:** authenticated multi-app broker, profiles/grants, Android SAF
  persisted permissions/provider and browser OPFS integration.
- [ ] **STORE-05:** release-grade backup migration/rollback, conflict handling,
  malicious inputs, interruption and disk-full recovery.
- [ ] **BOOK-01..06:** Sanctissimissa public-domain catalogue connection and one
  rights-verified edition through shared reading and retrieval.
- [ ] **REL/ACC:** signed native Tauri Windows/Linux/Android packages, update
  rollback, accessibility and named-device performance evidence. A Linux Node
  portable package is a separate format, not those native installers.
- [ ] **Browser/visual QA:** actual rendering, PDF selection, navigation, mesh
  gestures/roll, keyboard use, responsive layouts and reduced motion. Isolated
  DOM/API tests do not replace this acceptance.

## D. Mature knowledge and intelligence product

- [ ] **KG-01:** six-axis spatial interaction, saved views, accessible alternatives
  and performance validated on intended devices; camera math/code are present.
- [ ] **KG-02..04:** complete graph authoring/import semantics, provenance and
  large-corpus qualification, including optional authored semantic layers.
- [ ] **KG-05:** optional rare Fabergé-style Easter egg, opt-in game, mute/reduced
  motion and isolated scoring. It must not gate core use.
- [ ] **AI-01/02:** runtime/model/platform matrix, sustained load, cancellation/OOM
  recovery, thermals and large-context behavior. Actual LFM2.5 CPU evidence exists;
  Bonsai/ternary, Gemma-family and other quantizations need their own evidence.
- [ ] **TurboQuant:** integrate a backend implementing the intended KV compression
  and demonstrate correctness, memory and performance. Weight quantization and a
  UI/backend label do not satisfy this gate.
- [ ] **Web inference:** WebGPU/WASM adapter, capability/error handling, OPFS
  models and browser-specific performance/compatibility.
- [ ] **AI-03/04:** representative grounded tasks, real embedding retrieval
  quality, citation entailment, conflicting evidence and explicit homestead/
  hosted-provider privacy/cost consent. Citation mapping is not entailment proof.
- [ ] **CREATE-01..03:** mature editor/clipper, rich exports, authoring/merge,
  explicit publication and receipts. Private local revisioning exists.

## Release evidence template

Requirement ID / owner / exact revision / platform and hardware / artifact hashes /
procedure / expected and actual result / evidence / reviewer / remaining defects.
Record build, unit tests, integration, actual inference, visual QA and commercial
acceptance separately. An unchecked full requirement can have useful tested
subcomponents without being complete.
